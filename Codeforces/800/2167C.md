# 🪄 Isamatdin and His Magic Wand

*A story about reachability, parity, and when sorting is actually allowed.*

---

## 🎯 Problem in One Breath

Isamatdin has **n toys** in a row. Each toy has a number. If they’re not sorted, trouble follows 😬.

He owns a **broken magic wand** that can swap **only**:

* one **even** number 🔵
* with one **odd** number 🔴

The mission:

> **Produce the lexicographically smallest arrangement possible** using only those swaps.

---

## 🧠 Mental Model: This Is Not a Sorting Problem

At first glance, it screams *sorting*.

It’s not.

This is a **reachability** problem.

The question isn’t:

> *How do I sort?*

It’s:

> *Am I even allowed to rearrange?*

---

## 🧩 The Key Constraint (The Broken Rule)

You may swap two positions **i** and **j** **only if**:

```
a[i] % 2 != a[j] % 2
```

Meaning:

* Even ↔ Odd ✅
* Even ↔ Even ❌
* Odd ↔ Odd ❌

Parity is the gatekeeper.

---

## 🔍 Observation That Collapses the Problem

### Case 1️⃣: Both Even *and* Odd Exist

If the array contains:

* at least one even **and**
* at least one odd

Then something powerful happens ⚡

➡️ Any element can be moved anywhere.

Why?

* An even can swap with an odd
* That odd can then swap with another even
* Which creates a **bridge** between all positions

📦 The array becomes **fully connected**.

**Result:**

> You can achieve **any permutation**.

So the lexicographically smallest one is simply:

➡️ **The fully sorted array** ✅

---

### Case 2️⃣: Only One Parity Exists

If all numbers are:

* only even **or**
* only odd

Then:

* No valid swap exists 🚫
* The wand does nothing

📦 The array is **frozen in place**.

**Result:**

> The original sequence is already the smallest you can get.

---

## 🧪 Strategy (Executable Logic)

* Scan the array
* Detect whether **both parities exist**
* If yes → sort
* If no → output as-is

That’s it.

No simulation. No graph. No overthinking.

---

## 🧾 The Code (Minimal and Honest)

```cpp
#include <iostream>
#include <bits/stdc++.h>
using namespace std;

int main(){
    int t, n;
    cin >> t;
    
    while(t--){
        cin >> n;
        vector<int> nums(n);
        pair<bool,bool> even_odd = {false,false};
        
        for(int i = 0; i < n; i++){
            cin >> nums[i];
            if(nums[i] % 2)
                even_odd.second = true; // odd exists
            else
                even_odd.first = true;  // even exists
        }
        
        // If both parities exist, full sorting is possible
        if(even_odd.first && even_odd.second){
            sort(nums.begin(), nums.end());
        }
        
        for(int x : nums)
            cout << x << " ";
        cout << '\n';
    }
}
```

---

## ⏱ Complexity & Constraints

* Scanning parity: **O(n)**
* Sorting (only when allowed): **O(n log n)**
* Memory: **O(n)**

Safely within limits 🟢

---

## 🧠 Final Takeaway

This problem teaches a quiet lesson:

> **Freedom matters more than technique.**

Once freedom exists (both parities present), sorting is trivial.

Without it, no algorithm — no matter how clever — can move a single toy.

🧩 First ask *what is reachable*.
🧠 Only then decide *how to optimize*.

That’s not just competitive programming.
That’s systems thinking.

✨ End of story.
