# 😴 Sleeping Through Classes — A Countdown You Can’t Ignore

> *A story about exhaustion, hard rules, and a timer that controls your fate.* ⏳

---

## The Day

You have **`n` classes** today.

Each class is marked by a binary string:

* `'1'` → **important** 📚 (you must stay awake)
* `'0'` → **not important** 💤 (you *may* sleep)

Sounds easy… until the rule kicks in.

---

## The Rule ⚠️

If you attend an important class at position `i`:

> you must stay awake for the next **`k` classes**

That means:

```text
i, i+1, i+2, …, i+k
```

No naps allowed.

Even if those future classes are not important.

---

## The Goal 🎯

You are tired.
Very tired.

Your mission:

> **Maximize the number of classes you can sleep through.**

You cannot skip important classes.
You cannot shorten the cooldown.

You can only **count correctly**.

---

## The Hidden State 🧠

This problem is not about planning ahead.

It’s about tracking **one thing**:

> *How many classes am I still forced to stay awake for?*

Let’s call this the **awake countdown**.

---

## How the Day Actually Plays Out

We walk through the classes **from left to right**.

At each class, only three things can happen:

---

## Case 1: Important Class (`'1'`) 📢

```cpp
awake_count = k;
```

* you are awake now
* you will be awake for the next `k` classes
* any previous countdown is overwritten

No choice. No mercy.

---

## Case 2: Not Important & Countdown = 0 😌

```cpp
sleep_classes++;
```

* nothing forces you awake
* you sleep
* life is good

---

## Case 3: Not Important & Countdown > 0 😐

```cpp
awake_count--;
```

* you want to sleep
* but the rule says no
* the timer ticks down

Still awake.

---

## Why This Greedy Walk Works ✅

There is **no benefit** to staying awake voluntarily.

* sleeping earlier never blocks sleeping later
* every forced-awake class is unavoidable

So the optimal strategy is simple:

> **Sleep whenever the rules allow it.**

The code does exactly that.

---

## Reading the Code Like a Story

```cpp
int awake_count = 0;
int sleep_classes = 0;
```

One variable to track the curse.
One variable to track your wins.

---

```cpp
if (s[i] == '1') {
    awake_count = k;
}
```

An important class resets the timer.

---

```cpp
if (!awake_count) sleep_classes++;
```

No curse?
Sleep.

---

```cpp
awake_count = max(awake_count - 1, 0);
```

Time always moves forward.
The countdown never goes negative.

---

## Mental Model (Remember This) 🧠

Think of every important class as a **loud alarm** ⏰:

* it rings for `k+1` classes
* while it rings, you stay awake
* overlapping alarms just extend the noise

You sleep only in the silence.

---

## What This Problem Is Really Teaching 📘

This is a lesson in:

* state tracking
* greedy simulation
* understanding *forced constraints*

Not every problem needs DP.
Some just need a clean counter.
