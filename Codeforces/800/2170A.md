# 🧩 Maximum Cost in a Numbered Grid

*A story about structure, locality, and why the biggest numbers prefer the edges—but never the corners.*

---

## 🌍 The World: A Predictable Grid

We are given an `n × n` grid. There is no randomness here—only order.

* ➡️ First row holds values `1 → n`
* ⬇️ Each next row continues the sequence
* 🔢 Final row ends at `n²`

This is a **row‑major**, strictly increasing grid.

Why this matters: **large numbers live close to other large numbers**.

---

## 🧮 The Rule: Cost Is Local

Each cell has a *cost* defined as:

```
cost = cell value + sum of side‑neighbor values
```

Neighbors only exist if they:

* ⬆️ share a top edge
* ⬇️ share a bottom edge
* ⬅️ share a left edge
* ➡️ share a right edge

🚫 Diagonals don’t count.

This is a local computation inside a global structure.

---

## 🔍 The Hidden Question

We aren’t really asking:

* ❌ Which value is largest?
* ❌ Which cell has most neighbors?

We’re asking:

> 🧠 *Which position maximizes value **and** neighborhood power?*

That leads to an immediate hierarchy:

* 🔻 Corners → 2 neighbors (weak)
* 🔸 Edges → 3 neighbors (better)
* 🔷 Inner cells → 4 neighbors (optimal)

The winner **must** be an inner cell.

---

## 📍 Where the Big Numbers Live

Because numbers grow left‑to‑right and top‑to‑bottom:

* 📈 Largest values cluster near the **bottom‑right**
* 🤝 Their neighbors are also large

The optimal cell is:

> 🎯 An inner cell as close as possible to `n²`

Not the maximum value itself (it’s stuck in a corner),
but the one step inside the boundary.

That cell touches **four large neighbors**.

This is the sweet spot.

---

## 🧠 The Formula Appears

Once `n > 4`, the structure stabilizes.

The same pattern always wins:

* 🧩 one large central value
* 🔗 four nearly‑as‑large neighbors

The sum collapses into:

```
maximum cost = 5 × (n² − n − 1)
```

✨ No simulation. Just geometry + monotonicity.

---

## ⚠️ Small Grids Break the Pattern

Tiny grids don’t have enough space for the invariant to form.

So we lock them down explicitly:

| 🧱 n | 💰 Maximum Cost |
| ---- | --------------- |
| 1️⃣  | 1               |
| 2️⃣  | 9               |
| 3️⃣  | 29              |
| 4️⃣  | 56              |

From `n ≥ 5`, the formula always holds.

This is classic system design:

> 🛠️ *Handle unstable states, then generalize.*

---

## 🧾 The Code: Compact and Certain

```cpp
#include <iostream>
using namespace std;

int main() {
    int t, n;
    cin >> t;
    while (t--) {
        cin >> n;
        if (n > 4) {
            cout << 5 * (n * n - n - 1) << endl;
        } else if (n == 1) {
            cout << 1 << endl;
        } else if (n == 2) {
            cout << 9 << endl;
        } else if (n == 3) {
            cout << 29 << endl;
        } else {
            cout << 56 << endl;
        }
    }
}
```

🧠 The program doesn’t *search* for the answer.

It **knows where the answer must live**.

---

## 🎁 Final Takeaway

This problem isn’t about summing neighbors.

It’s about recognizing invariants:

* 📐 Structure dictates influence
* 📊 Value density increases predictably
* 🔁 Once stable, the same shape always wins

Great solutions don’t explore everything.

They go straight to the truth.

And stop.
