# Operations with Inversions — Eating From the Right

> *A story about dominance, patience, and why the right side always loses.*

---

## The Rules of the World

You are given an array:

```text
a1, a2, …, an
```

An operation is allowed if you can find indices `i < j` such that:

* `ai > aj`
* you **remove `aj`**
* the remaining elements keep their relative order

You may repeat this operation as long as it is legal.

Your task:

> **Maximize the number of removals.**

This is not about sorting.
This is about **who survives**.

---

## What Actually Matters

Notice what you are allowed to remove:

* only the **right element** of an inversion
* only when there exists a **larger element to its left**

You are never allowed to remove a dominating element.
Only the dominated ones die.

So the problem quietly asks:

> How many elements can eventually be proven unnecessary?

---

## A Key Observation

Suppose an element has **no greater element to its left**.

Then:

* it can *never* be removed
* no future operation can make it removable

These elements are **immortal**.

Every other element —
those that have a larger number somewhere to the left —
are **potential food**.

---

## The Greedy Strategy

To maximize removals:

* we want every possible smaller element
* to be eaten by the **nearest larger element to its left**

But deletions change indices.

So instead of simulating removals directly,
we reverse time.

---

## Looking From the Right

We scan the array **from right to left**.

Why?

Because an element can only be removed
by something that appears **before** it.

When scanning backwards:

* the stack represents elements to the **right**
* the current element is a potential **predator**

---

## The Stack as a Food Chain

Let the stack store elements that are:

* to the right of the current index
* still alive
* waiting to be dominated

Now consider `nums[i]`.

```cpp
while (!st.empty() && nums[i] > st.top()) {
    st.pop();
    count++;
}
```

This loop means:

* if `nums[i]` is larger than something to its right
* that right element **can be removed**
* and should be removed immediately

Why immediately?

Because waiting never helps.
If it can be eaten now, it can always be eaten later.

Greedy is safe.

---

## Why This Counts the Maximum

Every element is pushed once.
Every element is popped at most once.

An element is popped **if and only if**
there exists a larger element to its left.

That exactly matches the problem’s rule.

No removable element survives.
No irremovable element is touched.

---

## The Survivors

After the loop ends, the stack contains:

* elements that never had a larger value to their left
* the **prefix maxima** of the array

These are untouchable.

Everything else has been counted and removed.

---

## Complexity Reality Check

* Time: **O(n)** per test case
* Space: **O(n)**

Given `n ≤ 100`, this is comfortably fast.

More importantly —
it scales cleanly and predictably.

---

## Mental Model (Cache This)

Imagine the array as a line of creatures.

* Bigger numbers dominate smaller ones to their right
* Once dominated, a creature disappears
* The strongest to the left determine who survives

Scanning from the right lets you
watch the food chain collapse in reverse.

---

## What This Problem Is Really Teaching

This is not about inversions.

It’s about:

* monotonic stacks
* irreversible dominance
* counting deletions without simulating deletions

Once you see it,
this pattern appears everywhere.
